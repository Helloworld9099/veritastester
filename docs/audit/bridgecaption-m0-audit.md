# BridgeCaption M0: audit and frozen development baseline

**Review required before M1.** Audited [main at `7ad5f9e0`](https://github.com/Helloworld9099/veritastester/tree/7ad5f9e0b198020cf11ce35aa269206bb34de87b) and live research refs on 2026-11-20. The end state is **one user-facing multilingual bot** behind a stable interface; separate specialists and a future approved shared model may coexist behind it. This milestone does not consolidate neural weights, train, replace a provider, launch a release, change production code or merge to main. A single shared checkpoint is a separate model decision, not a requirement for one bot.

## Frozen development evidence

[Fixtures](../../tests/fixtures/multilingual_regression_v1.jsonl) and [manifest](../../tests/fixtures/multilingual_regression_v1.manifest.json) pin 18 newly authored, non-sensitive inputs: `m0-en-es-01…06`, `m0-es-en-01…06`, `m0-fr-en-01…06`. Source/reference pairs cover ordinary text, slang and idiom, negation, quantities, names, and omission risk. References are illustrative, not independent bilingual gold. Exact candidate outputs were identical **18/18 in two fresh offline CPU processes**, using unchanged #43 research Pipeline and pinned decoders/weights. Some frozen translations lose nuance; they are snapshots, not reference answers or training targets. The runner rejects prior context; contextual equivalence and private Mandarin are explicit gaps. Archived #43 20/20 development parity and used FLORES/500-case review materials do not count as new holdouts. No sealed final benchmark was opened.

Two-process peak RSS: **869,736 / 859,552 KiB**. Warm values each summarize 12 sequential calls on the pinned host; cold loading/first decode is separately in the manifest; no end-to-end audio baseline. Do not use this sample to claim the 10% gate has passed: later comparisons must repeat the pinned host/image, input mix, threads, timing boundaries and runs. Reproduce by checking out #43 at the pinned source, verifying each manifest base file and adapter hash, configuring the offline registry adapter/base roots and package versions, and replaying the three directions in sorted order twice in fresh processes through `Pipeline.translate` with the manifest Torch and decode settings; compare the complete decoded output strings before computing latency percentiles. Cross-platform parity is not verified.

**Existing product baseline:** With Python 3.12, credential-free, no optional ASR model, `python -m compileall -q src tests` and `python -m pytest -q` were run at the audited main. **165 passed, 1 skipped, 10 pre-existing failures** in `tests/test_overlay_interface.py`: nine instances of fixture objects missing `engine_selected`, plus one display width limit mismatch (expected ≤240, actual 320). This is a red baseline, not remedy authorization or proof of a live crash. Existing provider, pipeline, CLI and context code was not changed to make it green.

## Integration risks and preservation

- **#43 reuse, not whole-branch merge.** It is based on the Spanish feedback branch, above #40→41→42. It already supplies the design to reuse, but it also changes production slang hints in `src/bridgecaption/context.py`. Plan attributable, narrow adoption of only the reviewed registry/runtime work after approval. Separate the prompt change, keep old pathways, and never bring in the entire research ancestor stack. Main already contains archived restricted weights; Git ancestry is not weight ancestry. No externally owned branch was modified.
- **#39, #42 and subsequent Spanish branch:** restricted French WMT24 is not routed. ES active checkpoint `3bf849bb…` remains development-only. In its earlier Spanish lineage, the byte-matched `55d4…` adapter is reported as a fresh Europarl LoRA; draft shorthand differs. Reconcile this and all corpus notices before commercial adoption. #42 already implements opt-in length bucketing and accumulation; benchmark, do not duplicate. #36 is separate desktop packaging/update work, and #3 is a stale preflight patch with relevant behavior already on main. See the appendices for overlaps, work status, and Actions triggers.
- **Exact preservation gate for infrastructure:** immutable adapter/manifest SHA-256, same explicit direction matrix, identical pinned CPU outputs, exact architecture/tokenizer/base checks before loading, unchanged provider and privacy, appropriate license isolation, no hidden promotion. Source and fixture evidence exist; a consolidated automated gate, dummy-language additivity check, and application launch/audio regression for the refactor are still gaps. The red existing test baseline must be accounted for explicitly, not silently reported as passing.
- **If models are separately authorized later:** maximum 0.5 absolute chrF development regression per direction, zero new confirmed critical meaning errors, no material subgroup degradation; warmed p95 and peak RSS at most 10% worse under a matched environment unless separately approved. Automated diagnostics do not substitute for independent bilingual review. Keep commercial/research lineages isolated, preserve better specialists and record rollback per direction. No promotion without explicit user approval.
- **Rollback:** M0 is additive on a dedicated branch; ignore the branch or revert the audit commit in place if needed, retaining history. No schema, model, workflow, installer or provider migration needs undoing. Later milestones should preserve legacy entry points, exact reference pins, and isolated research checkpoints so a bad version can revert per direction without overwriting or deleting any artifact.

**Stop here.** No M1 work is authorized by this audit. Before treating parity as a migration gate for Mandarin, replay the exact private stack on appropriate CPU resources and keep its evidence private; no substitute base or speculative accuracy claims.
