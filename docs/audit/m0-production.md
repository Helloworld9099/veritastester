## Production versus research
- The shipped-facing source is a Python/Tkinter desktop app (`pyproject.toml` version 0.1.0; `bridgecaption = bridgecaption.app:main`; `__main__.py` delegates to app). `app.py` has EN, ES, FR among many selectable source/target languages, Auto→English default, with no user-facing provider picker. Selection is installation configuration `BRIDGE_TRANSLATOR`, default **Gemini** (`GEMINI_MODEL` default `gemini-3.5-flash-lite`). Groq and Gemini are contextual clouds, Ollama local contextual, Azure text-only cloud; no implicit fallback. `provider.py` and `providers.py` define request, model settings, availability/credential checks and transport. Cloud consent is scoped to the provider and tells users when contextual utterances/glossary can leave their computer.
- Live audio is locally transcribed with faster-whisper, default `base`, and `session.py` feeds detected or forced source language into `Pipeline.translate`; typed text runs a separate Pipeline/history; language change/reset prevents stale captions/history; same-language transcripts bypass translation. Context uses bounded preceding utterances, glossary, optional `BRIDGE_CONTEXT_MODEL`/ `BRIDGE_SENSE_MODEL` and source-language slang hints. Main has **no local Marian translation route**, no registry and no merged EN/ES/FR weights. Product EN↔ES, EN↔FR, ES↔FR are selectable requests to the configured provider, not verified six-direction quality claims. Research registry covers only ES→EN, EN→ES and FR→EN. FR→EN does not imply EN→FR; do not present ES↔FR as locally trained or evaluated.
- At main→#43 head diff, app, provider factory, Pipeline, session, packaging metadata, and existing tests are unchanged; **one product module changes**: `src/bridgecaption/context.py` adds EN/ES slang hints and normalizes hyphenated source codes (`es-MX`→`es`). Therefore merging #43 wholesale is *not* a zero-prod-behavior change: contextual prompts can change via `provider.py`'s hint use. Productized refactor should split/guard that behavior and regress ES and EN prompt/context output, preserving FR and cloud consent.
- Main CLI surfaces: `bridgecaption`/ `python -m bridgecaption`, `bridgecaption-check`, `bridgecaption-preflight`, `bridgecaption-train`, `bridgecaption-train-memory`, `bridgecaption-train-sense`, `bridgecaption-train-idiom`, text/context/audio evaluation, annotate/corpus-prep/curriculum/review/export. These older sense/context/memory models are not equivalent to the research translation checkpoints. Main regression files include `test_providers.py`, `test_pipeline_context.py`, `test_pipeline_senses.py`, `test_session.py`, overlay/interface, diagnostics, corpus/preflight and offline research/eval tests. Desktop/audio portability is separate from translation quality.

## Rollback and no-regression boundaries
- Freeze current known-good product ref, existing provider/default and privacy behavior; pin route→base revision/tokenizer/adapter/config/decoding/version/license+SHA manifests; preserve every stage, receipt, prior checkpoints and byte identity. Existing #43 smoke pins separate French and Spanish active hashes and verifies two rollback translations; registry routes are not one multilingual weight file. Reject silent cross-direction, cloud, or NC research fallback; use explicit offline opt-in and clear unsupported direction at later implementation, not under M0.
- Research assets and artifacts have disjoint suitability/data-use; don't copy noncommercial WMT24/other adapters into production or treat a model's license as dataset clearance. Check artifact expiry versus immutable Git preservation before referring to durable checkpoint availability. Keep frozen holdout out of implementation/training; no human quality/six-direction accuracy claim from fixture, dev-parity, or model-run status. Separate pipeline fixtures (deterministic mocked audio/provider, no credentials/downloads) from gated model smoke; record exact code/model and tested/non-tested classifications.
