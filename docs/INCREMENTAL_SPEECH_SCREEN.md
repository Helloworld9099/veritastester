## What we verified

For BridgeCaption, "native incremental" means previously ingested audio is represented by cached acoustic state instead of being fed back through the encoder. The same resident checkpoint and acoustic state feed both the original-language transcript and the English translation, even when the source language changes. Separate task decoders are fine. Fixed lookahead and feature overlap are fine if previously consumed audio is not re-run at the neural encoder boundary; integrations should explain the distinction and instrument the real input. A rolling buffer can emit streaming captions while still re-encoding audio.

## Offline preflight for a real candidate

The new [trace validator](../research/unified_models/incremental_evidence.py) rejects full-prefix or overlapping-window re-encoding, release gaps, future audio, restarted acoustic cache, artifact reloads, missing caption channels and missing directions. It requires distinct source languages in the **same process**, one pinned checkpoint load, and each channel to emit both before EOF and a final after all released samples are encoded. The test models two serial utterances and is not a general app event schema. The validator reads only independently hash-pinned redacted JSON, needs no model packages, and runs locally:

```sh
PYTHONPATH=.:src python -m research.unified_models.incremental_evidence \
  --root "$LOCAL_EVIDENCE" --trace trace.json \
  --trace-sha256 "$TRACE_SHA" --checkpoint-sha256 "$MODEL_SHA" \
  --direction 'es->en' --direction 'fr->en'
```

Top-level record: schema version `1`, kind `bridgecaption_incremental_trace`, scope `open_development`, device `cpu`, sample rate `16000`, a method SHA-256, and the event array. Each event has `kind` and monotonic `t_ms`; see the validator for the exact additional keys. `load` is recorded on actual load, `start/end` on the capture boundaries, and `release.end` is the cumulative visible raw sample offset. `encode.start/end` are half-open raw sample ranges represented by each actual encoder invocation. `cache_in/cache_out` are opaque, increasing acoustic-state generation IDs, starting from zero at utterance reset. `draft/final` identify the observed output channel and the acoustic-state generation it read. Hold time, quality and rendered text are intentionally not assessed here. No raw media or captions belong in the trace.

A pass verifies **trace consistency only**. A runner could report its requested chunk sizes while silently projecting the whole prefix; independent inspection and hooks at the actual encoder, model load and output callbacks are required. This screen deliberately does not admit overlap/re-encoding even if narrowly bounded; such a runtime may still be benchmarked as a separate buffered arm. Synthetic tests cover positive and adversarial traces. Timings, memory, WER, meaning quality, critical errors and 60-minute behavior remain unverified.

## Recommended next step

Keep the single-model constraint. For a newly available checkpoint, verify rights and pins, inspect the actual encode path, then produce a two-direction, dual-caption CPU trace on the same public DEV clips before spending time on a long run. If no released checkpoint qualifies, use a cache-aware multilingual encoder and separate transcript/translation heads as the design for **one** model artifact, not an app cascade or specialist switch. Design work is possible now; training and quality claims require a separate rights and compute decision. A bounded Canary comparison is optional if a faster near-term buffered reference would change a decision; it cannot substitute for this gate. Keep Mandarin and other future directions additive and unclaimed until tested.
